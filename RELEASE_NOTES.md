# Super Matrix v0.3.0

## Agent Installation 1.2.0

The product release is `v0.3.0`; the agent-run installation document is version `1.2.0`. Use the exact uploaded `AGENT_INSTALL.md`, `supermatrix-v0.3.0.tar` and `SHA256SUMS` together. Verify their GitHub asset digests before extraction or execution.

This release follows one installation path through the recipient's own agent and existing tools. Its 57 checks cover 12 public roles, table and permission configuration, card callbacks, HTTPS/private-tunnel automation, LocalWatch, autostart, recovery and live acceptance. Every problem returns to the runbook's recovery section.

## New Platform Capabilities

- Public Lark operation/permission and card-callback inputs.
- Portable table queue, native table-provisioning contracts and verified-result boundaries.
- Public identity/principle inputs, three approved skills and licensed public knowledge seeds.
- Explicit per-platform configuration, dependency, authorization and evidence requirements.

## Updated Platform Capabilities

- Recorded executable/environment isolation and ownership-based recovery using the existing LocalWatch.
- Public Scheduler, Heartbeat, Watchdog and Localgit configuration and dependency inputs.
- Restricted Autobitable fixed-target prompt delegation, preserving the existing adapter and queue mechanisms.
- Closed export mappings, mandatory file validation, bilingual private-keyword scanning and current-tree/history/escaped-text checks.
- Approved dependency lockfile fixes and current production-audit receipts.

## Upgrade

Create a new isolated installation; this is not an in-place migration. Preserve existing data and credentials privately. Do not copy old profiles, databases, production records or event subscriptions into the new runtime. Old-version cleanup requires separate authorization after acceptance.

The public history is replaced and the old `v0.2.0` tag/Release removed under explicit authorization. Use a new clone in a separate directory and do not republish the old ancestry. Previously downloaded copies and third-party caches cannot be recalled by this operation.

## Verification Boundary

Exact package tests, sanitization scope, dependency audits and source provenance are recorded in `SANITIZATION_REPORT.md`. This bounded pilot does not claim full private-platform parity or substitute local fixtures for actual account authorization, group interaction, external relay delivery or reboot acceptance. Only the runbook's completed checklist permits an installation verdict of `VERIFIED`.
