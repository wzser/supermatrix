# Weekly CLI Upgrade - Root Review Checklist

This file is embedded by watchdog `weekly-upgrade.ts` `kickoffRootReview` for supermatrix-root. Every item is marked `[ok]`, `[warn reason]`, or `[N/A reason]`. Checklist evolution proposals go in `## Checklist meta` and are reviewed before this file changes.

## Changelog sources and coverage (mandatory)

watchdog 在派单前抓取 before→after 区间的 changelog 并嵌入 prompt；review 输出必须包含 `## Changelog coverage` 段，对区间内**每个版本号**逐行标注「影响 SuperMatrix / 不影响 + 原因」。watchdog report entry 会机器校验该段：缺段或漏版本 → review 判为不完整，最终报告不发出、reviewed 基线不更新。固定来源：

- claude-code: `https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md`（`## X.Y.Z` 段落）
- codex: `https://api.github.com/repos/openai/codex/releases`（tag `rust-v<version>`，release body 即 changelog）
- lark-cli: `https://registry.npmjs.org/@larksuite/cli`（仅版本号+发布时间，无正文；行为差异靠本 checklist 的探测项验证）
- kimi-code: `https://api.github.com/repos/MoonshotAI/kimi-code/releases`（tag `@moonshot-ai/kimi-code@<version>`，release body 即 changelog）；SM-PATCH / ACP 兼容性仍以 live probe 为准

watchdog 抓取失败（`unavailable`）时 root 必须自行取上述固定来源核对同一区间，coverage 段照常逐版本列出。

## claude-code

- CLI flags: verify `-p`, `--output-format stream-json`, `--verbose`, `--permission-mode bypassPermissions`, `--model`, `--effort`, `--resume`, and `--input-format stream-json` still exist with compatible semantics.
- Claude `--effort` capability: compare both the scheduled before/after `claude --help` wording and the no-model parser surface from `claude --effort <candidate> --version`; help text is not the complete capability authority. This machine's parser baseline accepts `low / medium / high / xhigh / max / ultracode`; exact `ultra` is invalid for Claude and must not be inferred from Codex. Any parser or wording change requires a real probe of the affected Claude target and same-review updates to `src/app/commands/setEffort.ts`, `/help effort`, the Claude command builder, and focused tests.
- stream-json schema: verify system/init/assistant/tool_use/tool_result/result records remain compatible with `backend-claude/streamParser.ts` type-dispatch and unknown-field tolerance.
- Verify success exit code 0, errors nonzero, and `--resume <session-id>` continuation semantics.
- Check new environment variables for runtime, dogfood injection, or attribution side effects.
- 登录态 / shared credential store（scheduled do-entry 的硬门，不把 token 交给 root review）：在 `claude update` 前后分别把 `claude --version` 与归一化后的 `claude auth status` 写入 `data/cli-upgrade.log`、`weekly-cli-upgrade.audit.jsonl` 和 `weekly-cli-upgrade.receipt`。Keychain 只从 service `Claude Code-credentials` 的捕获流中解析 `claudeAiOauth.scopes`，receipt 仅记录 `user:inference` 与 `user:profile` 的 present/missing 布尔值，绝不输出 credential JSON、access token 或 refresh token。每个阶段并发 3 次当前 Terminal-localwatch 继承进程树内、以 scheduled `spawn(..., {stdio:["ignore","pipe","pipe"]})` 直连运行的 interactive-terminal `claude auth status`，以及 3 次独立的 `launchctl asuser <uid> ... claude auth status`；两个 context 都齐全且均为 authenticated 或 quota 才通过。不得用 `/usr/bin/script` 伪造 pseudo-TTY：在该 piped stdio 下它没有可用 terminal，可能以 `tcgetattr/ioctl` 失败。`429 quota` / rate-limit 是 quota，不是 auth failure。
- 若上述任一 scope 缺失、auth status 明示未登录、未知失败、或任一 context 样本数不足，Claude Code 分支 fail closed：升级前失败则跳过 `claude update`，升级后失败则阻断 root review；只发 Console 告警并提示人工运行 `claude auth login --claudeai`，不自动 update/降级/logout、不删除 Keychain、也不触发浏览器登录。reboot/wake 仅在 receipt 登记 `next-scheduled-run-only` 的被动复查，不主动重启；禁止为了验收主动重启机器或主动唤醒。
- 隐形标记回归（暂停，2026-07-09）：记录 `claudeMarkerCheck=skipped`，不运行历史修复脚本；除非用户或 root 明确恢复上游检查。
- Model availability: read `CLAUDE_MODEL_ALIASES` and `AVAILABLE_CLAUDE_MODEL_IDS` from SuperMatrix `src/app/commands/setModel.ts`, probe every model with `claude -p --model <id> "ping"`, and compare the list with the upstream changelog. Record unavailable IDs and propose additions/removals.

## codex (@openai/codex)

- Upgrade transaction: capture the exact pre-upgrade `codex --version`. If `npm install -g @openai/codex@latest`, its version probe, or the post-upgrade `codex-default-model` compatibility check fails, reinstall `@openai/codex@<captured-version>`, verify the restored version, rerun the compatibility profile, and record both the failure and rollback result. Do not continue to root review on a failed compatibility or recovery check.
- CLI and effort contract: verify `exec --json --dangerously-bypass-approvals-and-sandbox --model --cd`. SuperMatrix must continue to pass effort via `-c model_reasoning_effort=<level>` and map `max -> xhigh`; 不把 `--thinking` / `--effort` 当作当前 Codex CLI flag。If a bundled model has a model-specific level such as `ultra`, verify per-model validation and batch behavior before exposing it through global `/effort`.
- Stream JSON schema: verify reasoning, assistant, completed, error, and usage records remain compatible with `backend-codex/streamParser.ts`.
- Check reconnect/retry progress-error prefixes used by `replier.ts` and whether `model_context_window` is still reported. If it is absent, do not invent a context-window fallback; keep the UI denominator hidden until a verified value exists.
- Model availability and default: read `src/ports/CodexModelCatalog.ts` and run a minimal probe for each candidate. `codex debug models --bundled` and `supported_in_api=true` describe the bundled binary catalog; bundled catalog 不等于当前登录可用性。A rejection such as `not supported when using Codex with a ChatGPT account` must remove the model from the user-facing catalog, aliases, fallback, and `/help model`, or introduce a login-aware filter. Compare additions/removals with the upstream changelog and propose or auto-fix the catalog as appropriate.
- **sm-proxy / DeepSeek 通道是正常机制，不是故障**：probe 返回 `sm-proxy strict mode: requested model 'X' is not served by this route (served model: 'deepseek-...')` / `code: model_not_served` 时，这是 sm-switch 的账号/额度路由切换（本机 codex 流量临时走 DeepSeek 通道），属账号态 transient——**不要**据此把 OpenAI 系模型从 catalog/aliases/fallback/`/help model` 移除、改默认模型或提出"模型退役"类调整；checklist 结论标 `[N/A route-level transient (sm-proxy)]` 即可。路由归属 sm-switch / codexroot；若怀疑切换本身异常，Proposed for human 提请人工找 sm-switch 确认，不做代码调整。同样，probe 流里的 `Skill descriptions were shortened to fit the 2% skills context budget` 是良性提示，不是错误。2026-08-06 实例：08:44 全绿、16:04 全部 `model_not_served`，即为当日 sm-switch 切换所致。

## Kimi Code

- Runtime identity and upgrade: use the `SM_KIMI_CLI_PATH` selected by SuperMatrix, not a separately installed legacy `kimi-cli`. The scheduled upgrade step uses the documented Kimi Code installer because `kimi upgrade` is interactive and in a non-TTY only prints a manual command. Confirm `kimi --version` changed or report the typed upgrade failure; never call this successful merely because `kimi upgrade` exited 0.
- Binary transaction: before the installer, copy the exact selected Kimi binary and executable mode to a private temporary snapshot. Installer, version-probe, SM-PATCH, or newly degraded `kimi-acp-health` failure must atomically restore that snapshot, rerun the idempotent SM-PATCH verifier, require the original version plus marker count `>= 1`, and rerun the compatibility profile. Delete a successful snapshot; retain and report its exact path only when rollback itself fails.
- SM-PATCH recovery is a hard post-installer gate: after every completed Kimi Code installer run, immediately execute `python3 /Users/LOCAL_USER/SuperMatrix/scripts/kimi-sea-autonomous-turn-patch.py` with no binary override. The script is idempotent and performs its own backup, `node --check`, ad-hoc signature, and `--version` verification before replacement. Then require `strings ~/.kimi-code/bin/kimi | grep -c "SM-PATCH"` to be `>= 1`; record `kimiPatch.status` and `markerCount` in the weekly audit/receipt. Any future kimi-code installer path must call the same `runKimiAutonomousTurnPatch` helper rather than bypassing this gate.
- SM-PATCH failure handling: an anchor-count/layout-slack failure, script exit failure, or marker count `< 1` is a failed Kimi upgrade, not a warning. Write the failure into the audit/receipt and send the idempotent failure handoff to `codexroot（T800）` with key `<YYYY-MM-DD>:watchdog:kimi-sm-patch:codexroot`. Do not modify the patch script, hand-edit the binary, or silently continue to root compatibility review; T800 owns any script change after diagnosing upstream kimi-code binary drift. If the handoff itself fails, preserve that failure in the Kimi result and Console error notification.
- ACP contract: verify `kimi acp`, the initialize/new-session model metadata, supported protocol version, `session/update` event shapes, permission options, cancellation, and resume/load-session semantics remain compatible with `backend-kimi/acpClient.ts` and `backend-kimi/eventTranslator.ts`.
- Autonomous-turn perception contract (added 2026-08-07 after the aftersale-web incident): an idle session woken by a background-task completion notification starts an autonomous turn that SuperMatrix must be able to see. Verify the session wire log (`agents/main/wire.jsonl`) still records such turns in a recognized shape — `turn.steer`, or (kimi-code 0.33.0) `turn.prompt` whose first text block starts with `<notification`, matched by `isWireNotificationPrompt` in `src/app/kimiAutonomousTurnStream.ts`. Probe with `node /Users/LOCAL_USER/SuperMatrix/scripts/probe-kimi-acp.mjs bgturn` against the freshly patched binary and inspect the wire shape, not just the ACP stream. A new recording shape makes autonomous turns invisible — no busy flag, no violet card, user runs race the turn at the ACP layer. Any drift fails closed and hands off to codexroot; do not mark `[ok]` on ACP-stream visibility alone.
- Busy-rejection retry contract (added 2026-08-07): while a turn is active, a second prompt must be rejected with text matched by `isTurnActiveError` in `src/adapters/backend-kimi/index.ts` — currently `Cannot launch a new turn while another turn` or the 0.33.0 `another turn is already in progress`. Probe: start a long-running (or autonomous) turn, issue a second ACP prompt, and compare the exact rejection text against the adapter regex. A changed message bypasses the bounded wait-and-retry and fails user runs in ~2s with a red card (2026-08-07: 5 aftersale-web runs). Drift → fail closed, hand off codexroot.
- Card-ask delivery window (added 2026-08-07): the ask_user broker waits up to 300s for a human click, so the MCP tool call to the ACP-injected `askserver` must outlast that window. ACP `session/new mcpServers` cannot carry a per-server `toolTimeoutMs`, so SuperMatrix sets `KIMI_MCP_TOOL_TIMEOUT_MS=330000` on the shared ACP child (`buildKimiChildEnv` in `src/adapters/backend-kimi/acpClient.ts`). Verify the override is still honored — a click arriving after kimi's ~60s built-in MCP default must reach the model (2026-08-07: broker settled `answered` at 65s, the caller had already timed out with MCP error -32001; historically no click past ~60s had ever been delivered). Re-check whenever kimi changes MCP timeout precedence (per-server `toolTimeoutMs` > `KIMI_MCP_TOOL_TIMEOUT_MS` > `[mcp] tool_timeout_ms` > built-in default) or the broker window changes.
- Model surface: inspect the scheduled Kimi `provider list --json` audit fields (model id, provider, upstream model id, display name, capabilities) before and after the upgrade. The audit must not persist provider credentials. A provider/model/capability change requires checking `src/ports/KimiModelCatalog.ts`, `KIMI_MODEL_ALIASES`, `src/app/commands/setModel.ts`, `/help model`, and the Kimi adapter tests in the same review. Do not retain the obsolete assumption that Kimi has no model catalog.

## SuperMatrix command surface

- Synchronous compatibility gate: immediately before the first CLI mutation and again after all mutations, run `cd /Users/LOCAL_USER/SuperMatrix && npm run --silent self-check -- --profile cli-upgrade`. Require schema version `1`, profile `cli-upgrade`, mode `observe`, a terminating process, and structured `codex-default-model` plus `kimi-acp-health` results. A baseline command/check failure skips every upgrade. A new Codex failure rolls Codex back; a new Kimi warning/failure rolls Kimi back; every rollback is followed by the same profile as a recovery check. If the post-upgrade command produces no structured report, retry it exactly once immediately; a second failure remains a failed weekly run, keeps root review blocked, and requires Console follow-up rather than an unattributed multi-CLI rollback. A profile timeout with a report, malformed report twice, unexpected exit/report mismatch, failed recovery, or unowned new failing check is also a failed weekly run and must not dispatch root review.
- Alias/catalog drift: `codex-default-model` warn detail `reasonCode=CODEX_ALIAS_CATALOG_DRIFT` sets `requiresAdjustment=true` but does not itself roll back a still-runnable CLI. A non-empty owner `fallbackSlug` also proves that SuperMatrix selected a runnable default; do not roll Codex back solely for that warning, even when no alias drift co-occurs. Use the profile's owner-derived referenced-model list and alias drift targets; intersect those with changed bundled records, then probe each affected referenced model and its bundled `upgrade.model` successor. Keep the fixed Claude/Codex BTW probes too. Do not copy the SuperMatrix alias/fallback registry into watchdog.
- Machine model audit: the scheduled do-entry must persist the Claude `--model` and `--effort` help surfaces plus accepted Claude effort parser values, reduced Codex bundled catalog, Kimi provider model surface, and exact BTW target probes before/after upgrade. Compare 升级前后 evidence in the root review; end with `MODEL_AUDIT_RESOLUTION: adjusted|unchanged|blocked`. `adjusted` requires an `Auto-fixed` commit receipt, and a required source adjustment may not report `unchanged`.
- Global backend model/effort catalog publish: the scheduled do-entry must union the current catalog selectable models with post-upgrade CLI-discovered models across Claude/Codex/Kimi, live-probe every current selectable model under the current account, attach each model's discovered effort candidates, and persist a complete `backend_model_effort_probe v1` snapshot. Model `available` requires a successful `live_probe`; explicit unknown/retired/no-access is `unavailable`; quota/rate-limit/timeout is `transient`; discovered but untested is `unverified`. Effort `available`/`unavailable` requires `live_probe` or `parser_probe`. Publish only through `/Users/LOCAL_USER/SuperMatrixRuntime/workspaces/wendangwang/bin/backend-model-effort-catalog publish --input <snapshot.json>`; write status, receipt, and catalog revision into the weekly receipt/report. Any read/snapshot/publish failure fails closed, sends an error notification, blocks root review, and must never fall back to direct `lark-cli` Feishu enum writes.
- `/model` and `/help model` are mandatory after every Codex CLI, Claude Code, or Kimi Code upgrade. Run `/help model` and `npx vitest run tests/app/commands/setModel.test.ts tests/app/commands/setModel.kimi.test.ts tests/app/commands/setModelEffortBatch.test.ts tests/app/commands/help.test.ts`. Verify aliases, current catalog, listed full IDs, examples, fallback/default copy, and root batch targets agree.
- If models are added, retired, renamed, or rejected by the current login, explicitly check the owning catalog (`src/ports/CodexModelCatalog.ts` or `src/ports/KimiModelCatalog.ts`), `src/app/commands/setModel.ts`, `src/app/commandRegistry.ts`, `src/app/replier.ts`, and their tests. If no model-surface change is needed, record `[N/A model surface unchanged]`; never omit this check.
- `/btw` lower-tier model lock is mandatory after every Codex CLI or Claude Code upgrade: Claude = `sonnet` (resolve the current Sonnet ID through the alias; do not pin an obsolete full ID), Codex = `gpt-5.5` (an explicit BTW target; do not reuse the global Codex default). Probe both exact targets and run `npx vitest run tests/app/commands/btw.test.ts`. A transient quota/rate-limit failure must not change the lock. If the upstream generation/tiering changes or a target is confirmed retired/renamed, update `src/app/commands/btw.ts` and its tests in the same review to the newly verified one-tier-lower model; if no unambiguous replacement exists, fail closed and propose a human decision instead of silently falling back to the highest/default model.
- `/effort` and `/help effort`: verify `low|medium|high|xhigh|max|default`, batch targets `all|all-claude|all-codex|all-kimi`, and `default` clearing behavior. Confirm the Claude allowlist matches the audited parser surface; exact `ultra` stays Codex-only, while `ultracode` requires parser acceptance plus a successful target-model probe before it is exposed. Run `npx vitest run tests/adapters/backend-claude/commandBuilder.test.ts tests/adapters/backend-codex/commandBuilder.test.ts tests/adapters/backend-codex/forkBootstrap.test.ts`; Claude uses `--effort`, Codex uses `model_reasoning_effort`, and fork/bootstrap inherit effort.

- Dependency transaction: require a readable pre-upgrade `lark-cli --version`, then snapshot the exact SuperMatrix `package.json` and `package-lock.json` bytes before `npm install @larksuite/cli@latest --save`. On installer or version-probe failure, restore both manifests, run `npm install --ignore-scripts` to converge `node_modules`, restore the exact manifest bytes again, and require the original CLI version. Record rollback failure and do not dispatch root review.
- Verify strict identity mode `--as bot|user`, `im +messages-send`, `im +messages-mget`, `im +chat-create`, `im +messages-resources-download`, `event +subscribe --compact --quiet`, and generic `api METHOD path` JSON envelope compatibility.
- Check migration signals for `event consume / _bus`; do not silently forward `_notice.update` into ordinary task final replies. 普通任务最终回复不应转述版本更新提示；version drift belongs to weekly CLI upgrade/report unless it directly explains the command failure.

- `base +record-list`: verify `.data.data` is the row array and `.data.has_more`, `.data.page_token`, and `.data.field_id_list` exist; require `--limit`, not `--page-size`, and do not require `.data.total`.

- Verify generic GET/POST/DELETE passthrough using safe test resources. If a change affects an owner such as wendangwang, either auto-fix a mechanical break or name the owner and mitigation in the final report. Keep the registry-gate check as `[N/A registry gate not deployed yet]` until it is implemented.
