# SuperMatrix v0.3.4 Installation

The installation document is AGENT_INSTALL.md version 1.2.0 for the v0.3.4
pilot. Give that document and its matching
archive to your own agent. It uses existing tools and configuration, not a new
SuperMatrix installer. Do not combine it with the older 1.0.1 archive. The
product target is v0.3.4; require S1's published metadata and asset digests
before execution. A local copy is not proof that a Release exists.

In the extracted archive the same document is at its root, `AGENT_INSTALL.md`.

Read the complete document before changing the machine. Initialize checklist C
and enforce S1's package gate. Inspect M/B/N/L before authorization, then follow
S1-S5, native platform configuration and V/H. Every platform needs configuration
and functional evidence, including required tables, HTTPS relay/private tunnel
for enabled automation, and LocalWatch/autostart. Missing public code and a
supported setting not yet configured are different gaps; neither is a pass.
For every error, uncertain result, interruption or context handover, return to
section R before another affected mutation. Diagnose and repair supported
configuration yourself; missing interfaces, unsafe ownership and package defects
require correction, not a replacement installer or a skipped check.

The pilot targets macOS Apple Silicon with a Codex runtime backend. It creates
an isolated runtime, Lark profile, control group and public platform groups.
It does not migrate an old installation or configure global authentication.

Native backend login, Lark consent, tenant approval and hidden SDK-secret entry
remain human actions. Never send credentials through chat or copy old account
files, databases or workspaces into this installation.

Do not follow the old v0.1.0 archive instructions, global CLI setup or LaunchAgent
installation procedures. Product release publication is not proof that the
document's complete checklist and live acceptance checks have passed.
